# File-review candidate packet

Unpack this entire folder anywhere, open a terminal in it, and run `node serve.mjs` using Node 24. Open <http://127.0.0.1:5194/> in your normal browser. No npm install, repository checkout, network service, or browser download is needed. If the port is in use, run `node serve.mjs 5195`. Stop with Ctrl+C. The server binds only to this computer and serves only files listed in SHA256SUMS. Opening index.html directly as a file does not support module loading.

Start with rubric.md. Record your own observations in observations.csv, which ships with a header and no observations. Keep a separate copy of the original packet before editing. Review the four candidates independently at 1280px and 320px in light and dark, including keyboard use. Reloading resets the simulated first-call service failure. This is a local simulation with no real upload, approval, authentication, or persistence service.

Candidate labels hide condition names; appearance and bundled code may reveal identity. Order is fixed by opaque ID, with all four candidates retained, including failures or unavailable builds. This is not perfectly blinded or randomized. Avoid inspecting JavaScript, source hashes, repository history, or the source revision before recording observations: those can unmask conditions. The packet has no condition key, generation prompts, manifests, or source maps. Source metadata exists for reproducibility, not scoring.

The links under Historical evidence are optional and should be opened after your independent review to reduce anchoring. evidence/primary/objective-results.json and the per-candidate primary browser/render reports are unchanged archived objective records. They include all original failures. Some primary interaction assertions used resting button names during pending-name changes; those failures are not established application failures. evidence/supplemental/summary.json is the unchanged supplemental summary, including its own render diagnostics and comparisons to primary results. Its corrected pending-control method was devised after viewing primary failures, so it is exploratory confirmation and does not replace primary endpoints. The summary's render details describe supplemental execution. Primary render reports remain under evidence/primary/. Original experiment files have not been rewritten.

SOURCE.json records replay time, source revision, exporter/replay identities, candidate App/CSS hashes, and the origin and hash of each included historical report. SHA256SUMS covers every packet file except itself. A fresh export verifies all 48 frozen input hashes and final source/prompt hashes, then replays only builds. Prompt and condition-fingerprint hashes are excluded from public metadata. Replay creates current playback assets; it does not rerun historical measurement. Any separate playback smoke report is a delivery check, not a new experiment result or human review.

This comparison has one task, four attempts, one requested model alias, unequal documentation exposure, and workspace isolation by instruction. It measures a combined package/guidance treatment; the task is not guaranteed unseen. Automated checks cover only parts of interaction, layout and accessibility. Mixed-selection semantics, updated per-file status wording, complete rejection keyboard operation, native assistive technology, disabled-user evaluation and independent human design judgment remain open. No general quality winner, AI-superiority claim, accessibility conformance or human score follows from these reports.

To check packet integrity before editing, compare each file's SHA-256 to SHA256SUMS using your operating system's checksum tool. Editing observations.csv changes its checksum as expected. Report observations through the beta's existing reviewer call; this server sends nothing automatically.
